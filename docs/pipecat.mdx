Pipecat is an open-source framework for building voice agents from separate STT,
LLM and TTS services. `JambonzFrameSerializer` connects a Pipecat pipeline to a
jambonz call over a WebSocket, so the agent receives the caller's audio and
speaks back on the same connection.

Unlike the [agent](/verbs/verbs/agent) verb, which orchestrates the turn cycle
inside jambonz, here Pipecat owns the pipeline and jambonz provides the call.
Use this when you already have a Pipecat application, or when you want the
turn-taking, context handling and tool calling to live in your own code.

## The verb

```json
{
  "verb": "listen",
  "url": "wss://your-bot.example.com/ws",
  "sampleRate": 16000,
  "mixType": "mono",
  "passDtmf": true,
  "bidirectionalAudio": {
    "enabled": true,
    "streaming": true,
    "sampleRate": 16000
  }
}
```

<Warning>
`bidirectionalAudio.streaming` defaults to `false`, and while it is false the
audio your application sends back is discarded. Nothing is logged and no error
is raised — the caller simply hears silence.
</Warning>

### Sample rates

Three properties interact here, and only one of them has a default you would
want.

`sampleRate` sets the rate jambonz forks the caller's audio at. It defaults to
`8000`; `16000`, `24000`, `48000` and `64000` are also allowed. The serializer
reads whichever rate you chose out of the preamble, so the same agent handles a
narrowband PSTN call and a wideband call with no code change — but if you want
wideband you have to ask for it here.

`bidirectionalAudio.sampleRate` sets the rate your returning audio is
interpreted at. It has no default: omitted, your audio is read at the call's
negotiated codec rate, which is 8 kHz for PCMU or PCMA and higher for a
wideband codec. That depends on the carrier and on what the far end offered, so
it is not something to leave to chance.

jambonz does not require the two to be equal — it resamples whatever arrives at
`bidirectionalAudio.sampleRate`. The constraint comes from the serializer,
which sends at the `sampleRate` it read from the preamble and is never told the
return rate.

<Note>
**With this serializer, set `bidirectionalAudio.sampleRate` to the same value
as `sampleRate`.** If they differ, playback runs fast or slow by exactly that
ratio.
</Note>

### mixType

`mixType` defaults to `mono`, which is what you want. The serializer refuses
the other two and says why in the log:

- `stereo` sends both call legs as two interleaved channels. Read as mono, that
  plays at double speed with the channels alternating.
- `mixed` is a single channel, so it would decode correctly — but it is both
  legs summed together, which means it carries the agent's own audio back to
  it.

## A minimal agent

```python
import os

from fastapi import FastAPI, WebSocket

from pipecat.audio.vad.silero import SileroVADAnalyzer
from pipecat.frames.frames import LLMRunFrame
from pipecat.pipeline.pipeline import Pipeline
from pipecat.pipeline.worker import PipelineParams, PipelineWorker
from pipecat.processors.aggregators.llm_context import LLMContext
from pipecat.processors.aggregators.llm_response_universal import (
    LLMContextAggregatorPair,
    LLMUserAggregatorParams,
)
from pipecat.serializers.jambonz import JambonzFrameSerializer
from pipecat.services.cartesia.tts import CartesiaTTSService
from pipecat.services.deepgram.stt import DeepgramSTTService
from pipecat.services.openai.llm import OpenAILLMService
from pipecat.transports.websocket.fastapi import (
    FastAPIWebsocketParams,
    FastAPIWebsocketTransport,
)
from pipecat.workers.runner import WorkerRunner

app = FastAPI()


@app.websocket("/ws")
async def jambonz_call(websocket: WebSocket):
    await websocket.accept()

    transport = FastAPIWebsocketTransport(
        websocket=websocket,
        params=FastAPIWebsocketParams(
            audio_in_enabled=True,
            audio_out_enabled=True,
            serializer=JambonzFrameSerializer(),
        ),
    )

    context = LLMContext(
        [{"role": "system", "content": "You are a receptionist. Keep replies to one sentence."}]
    )
    user_aggregator, assistant_aggregator = LLMContextAggregatorPair(
        context,
        user_params=LLMUserAggregatorParams(vad_analyzer=SileroVADAnalyzer()),
    )

    pipeline = Pipeline(
        [
            transport.input(),
            DeepgramSTTService(api_key=os.environ["DEEPGRAM_API_KEY"]),
            user_aggregator,
            OpenAILLMService(api_key=os.environ["OPENAI_API_KEY"]),
            CartesiaTTSService(
                api_key=os.environ["CARTESIA_API_KEY"],
                voice_id=os.environ["CARTESIA_VOICE_ID"],
            ),
            transport.output(),
            assistant_aggregator,
        ]
    )

    worker = PipelineWorker(pipeline, params=PipelineParams(enable_metrics=True))
    runner = WorkerRunner()
    await runner.add_workers(worker)

    @transport.event_handler("on_client_connected")
    async def on_client_connected(transport, client):
        await worker.queue_frames([LLMRunFrame()])

    await runner.run()
```

The serializer takes no configuration. The sample rate, the channel layout and
the call's identifiers all come from the JSON preamble jambonz sends before any
audio.

Once the preamble has arrived, `serializer.call_sid` and
`serializer.trace_id` are available for correlating your logs with jambonz's,
and `serializer.call_meta` holds the whole preamble.

## DTMF

With `passDtmf` set, a digit arrives as a text frame on the same socket and
becomes a Pipecat `InputDTMFFrame`:

```json
{ "event": "dtmf", "dtmf": "5", "duration": "1600" }
```

Handle it like any other frame:

```python
from loguru import logger

from pipecat.frames.frames import InputDTMFFrame
from pipecat.processors.frame_processor import FrameDirection, FrameProcessor


class CollectDigits(FrameProcessor):
    async def process_frame(self, frame, direction: FrameDirection):
        await super().process_frame(frame, direction)
        if isinstance(frame, InputDTMFFrame):
            logger.info(f"caller pressed {frame.button}")
        await self.push_frame(frame, direction)
```

`mark` and `playDone` replies arrive on the same socket and are ignored.

## Ending the call

The agent can hang up. When the pipeline ends, the serializer sends
`disconnect`, which ends the `listen` verb — after which jambonz runs the
verb's `actionHook` if it has one, and otherwise hangs up the call. There are no
API credentials to configure.

```python
from pipecat.frames.frames import EndFrame

await worker.queue_frames([EndFrame()])
```

Pass `JambonzFrameSerializer.InputParams(disconnect_on_end=False)` if your
application ends the verb itself, or if the call should outlive the pipeline.

## Interruptions

When the caller talks over the agent, Pipecat raises an interruption and the
serializer sends `killAudio`, which flushes playing and buffered audio. Nothing
further is required: jambonz reads the socket in order, so the next turn's audio
queues behind the flush rather than racing it.

## Trying it

A softphone is enough — no carrier is needed.

1. Expose your agent on a public `wss` URL. During development, `ngrok http 8000`
   and use `wss://<id>.ngrok.app/ws` as the verb's `url`.
2. Point your application's call webhook at an endpoint that returns the verb
   above, and set it as the account's device calling application.
3. Register a softphone against your jambonz account and dial.

<Tip>
To exercise the narrowband path, set the softphone's codec to PCMU or PCMA and
set both rates in the verb to `8000`. That is the same audio geometry a G.711
PSTN carrier produces.
</Tip>
